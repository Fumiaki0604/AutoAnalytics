## レポート作成のルール

各仮説には検証ステータスが付いています。ステータスに従って判定してください。
- `supported`  : SQL結果が得られた → データに基づいて支持/棄却を判断する
- `no_data`    : 結果0行 → 「このセグメントには該当データなし」として記述する
- `error`      : SQL実行失敗 → 「検証不可」として記述し、原因を推測する
- `no_sql`     : SQL未生成 → 定性的な考察のみ記述する

## 文章・段落のルール

**段落構成**
- 各段落の最初の文でその段落が何の話かわかるように書く。結論を最後に持ってこない。
- 一つの段落には一つのトピックだけを書く。

**因果の説明**
- 「〜が増加した」で終わらず、なぜそうなったかのメカニズムをデータに基づいて説明する。説明できない場合は「原因は不明」と明記し、「未確定事項」に追記する。

**数値の書き方**
- 変化率だけでなく絶対数を必ず併記する。例:「セッション数が+23%増加（1,200→1,476件）」
- 割合を述べるときは分母を明示する。例:「全セッションの67%（6,388/9,414件）」

**セクション間の重複禁止**
- エグゼクティブサマリーに書いた内容を「主要な発見事項」でそのまま繰り返さない。エグゼクティブサマリーは最重要の結論のみ、発見事項は個別の定量的事実を書く。
- 仮説の「解釈」で書いた内容を「主要な発見事項」でそのまま言い直さない。発見事項には仮説を横断した新たな視点を加える。
